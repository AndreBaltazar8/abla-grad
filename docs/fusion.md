# `$fuse`: fused kernels from a chain of ops (design, 2026-11-24; to settle with e7 and e8 once df's profile says which chains first)

Idea (André): a compile-time subparser, as `$json`/`$glsl` are, so fusion is written once, shape-checked against the model's dimensions, and generated as one kernel;
CUDA C now, `@kernel` Abla (#1233) later behind the same notation. No compiler change: a subparser is a `compile fun` over a `ParserCursor` (docs/subparsers.md in ablac).

## Notation (Inkling example: the attention inputs of a sliding-window layer)
```abla
val attnInputs = $fuse attn_inputs_swa {
    dims   n = 2304, qd = 3072, kvd = 1024
    in     x: f32[n], norm: f32[n]
    in     wq: q8_0[qd, n], wk: q8_0[kvd, n], wv: q8_0[kvd, n]
    out    q: f32[qd], k: f32[kvd], v: f32[kvd]
    xn = rmsnorm(x, norm, eps = 0.000001)
    q = matvec(wq, xn)
    k = matvec(wk, xn)
    v = matvec(wv, xn)
}
```
and the MoE block of one layer visit (router, selection, indexed gate/up, SiTU, indexed down, combine are one launch each today; here a chain of two):
```abla
val experts = $fuse experts_nvfp4 {
    dims   n = 2304, ff = 1152, used = 8
    in     x: f32[n], ids: u32[used], weights: f32[used], gateUp: nvfp4[experts, 2*ff, n], down: nvfp4[experts, n, ff], scales: f32[experts]
    out    y: f32[n]
    g = matvec_indexed(gateUp, x, ids, scales)          // [used, 2*ff]
    a = situ(g, beta = 4.0, lb = 25.0)                  // [used, ff]
    d = matvec_indexed(down, a, ids, scales)            // [used, n]
    y = combine(d, weights)                             // [n]
}
```
Rules: a block declares `dims` (integer constants, may reference the model's compile-time constants), typed `in`/`out` tensors (`f32`, `u32`, or a weight storage type from
src/gguf/quant.ab; rank <= 3; extents are dims expressions), then single-assignment lines `name = op(args)` over a fixed vocabulary that is exactly the kernel
list in docs/kernels.md (rmsnorm, matvec, matvec_indexed, add, silu_mul, situ, softcap, sigmoid_mul, l2clip, scale, conv_step, ...). An unknown op, a shape mismatch
(`matvec(wq: [qd, n], xn: [m])` with m != n), a type the op has no kernel for, a name used before it is defined, or an out that is never assigned is a compile-time
error naming the line (`parserFail`).

## What it generates
The subparser returns an ordinary expression: `FusedKernel(name, source, argKinds, geometry, steps)`:
- `source`: one CUDA C kernel as a string constant (`extern "C" __global__ void <name>(...)`), generated by composing the ops' per-element/row device functions
  (each op in docs/kernels.md has a `__device__` form emitted from the same text as its standalone kernel, so there is one definition of every op) with the shapes
  baked in as `constexpr` (NVRTC sees the real extents: loops unroll, no runtime shape checks). Stages that need a block-wide result (a norm's sum of squares, a router's
  top-k) are computed redundantly or cooperatively per block as the generator decides (rule: redundant when the reduced vector is at most a few thousand floats).
- `argKinds`/`geometry`: the registry entry the CudaBackend needs (parameter kinds in the order of the `in`/`out` declarations; block size and items per block derived
  from the largest output extent).
- `steps`: the same chain as a list of unfused launches (`name`, ops, buffers) that the backend can run instead. This is the **reference path**: the model can run
  either (`ABLA_GRAD_FUSION=0` forces the unfused one), and the test below compares them.
`ops.ab` gets `opFused(backend, kernel, buffers...)`; `src/model/inkling.ab` keeps calling op functions, one per fused block instead of several.

## How it is tested
1. Every op already has a CPU-reference test (tests/kernels/*). A fused kernel is tested against its own `steps` (the unfused chain) on the GPU with the same random
   inputs: tolerance = the sum of the unfused ops' tolerances (written next to the block), plus an exactness check where the chain is only elementwise.
2. The generator is tested without a GPU: golden source strings for 3 small blocks (so a change of the generated text is a visible diff), and error tests: one
   `$fuse` per rule above that must fail to compile with the expected message (red test per rule, as the compile-time features of ablac do).
3. Model level: `tools/gate-inkling.sh` and `gate-llama.sh` pass with fusion on and off (same tolerances), and the speed table (tok/s) is recorded for each fused block.

## Phases
v0 elementwise and row chains over one reduction (norm -> matvecs, situ chains, residual+norm); v1 indexed MoE chains (above); v2 a whole attention block (needs the
KV-cache write and the sink-and-bias softmax as ops); v3 persistent kernels / the whole visit. The `@kernel` backend (#1233, e8) later emits the same
`FusedKernel` from the same notation with Abla code instead of CUDA C: the notation, shape checks and `steps` do not change, only the generator's output language.

## Open questions (for e7 / e8 after the profile)
- Which chains first: df's table decides (launch count and the single-block kernels first).
- Cooperative reductions across blocks (a matvec after a norm over a vector produced by another block) need a grid sync or a second launch: the generator should split the chain
  there (one launch per grid-wide dependency) rather than use cooperative launch, unless e7 measures cooperative groups as cheaper.
- Whether the generator emits tiled code for matvec itself or calls the hand-written device functions of the standalone quantized kernels (preferred: reuse, no second
  definition of a quantization layout).

## e7's review (2026-11-24), to be applied
- The quantized matvec sources already have row dots (`nvfp4_dot`, `q8_dot`, `k_dot`: packed row pointer, `const float* x`, `cols`, sum in lane 0): extract their CUDA text as a shared source prefix;
  the standalone wrappers stay as they are (runtime `cols`); a fused wrapper resolves row/expert, may stage x in shared memory, and passes constexpr `cols`. One full warp per row, whole-warp tails, any block
  barrier before the tail branch; keep dequant, FP32 reduction order and where the expert scale is applied. Bit parity with the standalone kernel and a repeat of the existing 4090 timings before claiming no slowdown.
- Reductions: cooperate within a block for a row/head-local norm. A global norm duplicated per CTA is only worth it when the fan-out is small: the Q/K/V bundle has 5,120 output rows, four rows per CTA repeats the
  2,304-value norm 1,280 times, so the baseline to beat is a separate norm + bundled projections. A true cross-CTA dependency (SiTU -> down projection) is a launch boundary; cooperative grid sync needs a different launch
  and a resident grid: deferred. Geometry follows the warp/tile mapping and the state writes, not the largest output extent alone (amends "What it generates").
- First hand-written candidate: indexed gate/up -> SiTU (a CTA pairs the gate and up rows of a slot, applies each expert scale before SiTU, writes only the activation); down stays separate. Also measure bundled Q/K/V/rel
  projections after the norm (the shared SWA input holds before the loop controllers; later passes can have distinct inputs). Local chains: conv -> head norm/clip -> KV store, residual -> norm. If the profile ranks
  depth_mix, moe_route or long relative attention high, parallel standalone versions go first so fusion savings are isolated.
